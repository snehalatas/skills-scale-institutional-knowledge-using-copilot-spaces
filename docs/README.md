# OctoAcme Project Management Docs

This folder contains OctoAcme’s project management guidance: a shared, lightweight operating model for initiating, planning, delivering, releasing, and improving cross-functional work. Use the overview as a starting point, then consult the process guide for the stage of your project or your role.

## Project management processes summary

OctoAcme follows an iterative lifecycle. **Initiation** validates the business need, aligns stakeholders, and defines measurable outcomes, an initial timeline, and key risks. **Planning** turns approved work into a prioritized and estimated backlog, with acceptance criteria, a Definition of Done, milestones, dependencies, and a QA approach. **Execution** delivers in small increments using a project board, regular standups, reviews, and progress and risk tracking. **Release and deployment** require acceptance criteria and CI/security checks to pass, release notes and rollback plans to be ready, and post-deployment checks and stakeholder communications to be completed. Throughout, the team maintains a risk register and shares updates through regular syncs and a common source of truth. **Retrospectives** after sprints, releases, milestones, or incidents turn learning into owned, time-bound improvement actions.

The PM coordinates delivery, risks, and communications; the Product Manager/Product Lead defines outcomes and priorities; developers build and test; QA validates quality and acceptance; and stakeholders provide input and approvals. Quality is supported by clear acceptance criteria and Definition of Done, code review and required approvals, automated tests and linting, integration and smoke testing where appropriate, security scanning, and manual QA when needed.
